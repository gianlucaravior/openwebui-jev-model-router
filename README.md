# JEV Model Router for Open WebUI

An Open WebUI inlet filter that uses Cloudflare-hosted JEV or Clef to choose which configured Open WebUI chat model should answer. JEV/Clef only make the routing decision. The final response is still generated by the selected Open WebUI model through its existing connection, including any Cloudflare AI Gateway configuration on that connection.

The filter uses Open WebUI model IDs in its decision and rewrites the request to the selected ID, so the selected response model remains visible in Open WebUI.

## How Routing Works

1. A user starts a conversation with the configured router-entry model.
2. The filter builds an eligible candidate list from active Open WebUI models. Model names and descriptions are sent once as compact choice options; tools are not repeated separately because relevant tool support should be described in the model description.
3. Cloudflare JEV/Clef evaluates the request and chooses one compact choice option. That option maps back to the original Open WebUI model ID. Its structured score estimates the context size needed for the conversation.
4. The filter changes the request model to the selected Open WebUI model and preserves that model's metadata, tools, knowledge and system prompt for the actual response.
5. An invisible marker in the assistant turn persists the selected model and whether the request was Voice Mode or text. The marker is encoded entirely with zero-width Unicode characters; legacy Base64 markers are still recognized and removed when encountered.
6. Later turns restore the route without calling JEV/Clef. A new decision is made when Voice Mode changes, or when a new image arrives but the previous model does not support vision. The conversation supplied to those decisions lets JEV/Clef assess context need; there is no context check on ordinary turns.

If a request includes images, the filter limits candidates to Open WebUI models marked with the Vision capability and uses the image/text decision model. Clef accepts embedded image data; remote image URLs are not forwarded to Clef because its API requires image bytes.

## Requirements

- Open WebUI 0.9.1 or later, matching the upstream filter's declared requirement.
- Python package `httpx` available in the Open WebUI environment.
- A Cloudflare account and API token with Workers AI Read permission.
- An AI Gateway ID when calling Workers AI through a specific gateway. The gateway must allow the configured token and model usage.
- Active Open WebUI response models. Descriptions are strongly recommended because they are the main basis for capability, tool and context-profile decisions; models without descriptions remain candidates.

JEV is TypeSafe's structured evaluator (`typesafe/jev`), not a chat completion model. Clef and Clef Flash use the same typed `state`/`questions` decision pattern; Cloudflare's REST request envelope differs by backend. Use Clef or Clef Flash for image-and-text decisions. JEV cannot inspect image pixels.

## Install and Configure

1. Install this file as an Open WebUI Filter Function. Set `filter_id` to the function ID shown in your installation, enable it for the router-entry model, and ensure Open WebUI accepts the filter ID inserted into routed metadata. This lets it restore the route on later turns and detect a Voice Mode change. Keep the router-entry preset's ID in `router_entry_model_id`.
2. Create a router-entry model/preset in Open WebUI. It must be a normal chat model because the decision service is not used to answer. Use it as the standard model users select to start a chat.
3. Set `router_entry_model_id` to that preset's Open WebUI model ID.
4. Configure `fallback_model_id` as an Open WebUI chat model ID. On a routing failure, this model is used. If it is empty or unavailable, the incoming model is left unchanged.
5. Set `cloudflare_account_id` and `cloudflare_api_token`. Keep the token secret and do not include it in logs or screenshots.
6. Set `cloudflare_gateway_id` if requests should use a specific AI Gateway. The filter sends `cf-aig-gateway-id` when this value is non-empty.
7. Choose `text_decision_model` and `image_text_decision_model`. For example, use `typesafe/jev` for text and `@cf/cloudflare/clef-flash` for image/text routing.
8. Configure `allowed_models` and `banned_models`, then add useful descriptions to the allowed Open WebUI models.
9. Test with a new text chat, an image request, a Voice Mode turn and a Voice Mode/text mode switch. Ordinary follow-up turns should not make another Cloudflare decision request.

The Cloudflare token is sent server-side from Open WebUI to the Cloudflare API. It is not sent to the browser. The masked valve may not display its saved value when you reopen the dialog; that alone does not mean the value was lost. With debug enabled, logs show the account ID and whether a token is configured, but never log the token itself. JEV/Clef requests include the conversation content needed for routing, so review your Cloudflare data-handling settings before enabling this filter for sensitive chats.

## Valves

| Valve | Purpose |
| --- | --- |
| `router_entry_model_id` | Open WebUI model ID users select to begin automatic routing. |
| `filter_id` | Filter/function ID placed into routed model metadata to keep this filter active on follow-up turns. Set this to the ID shown by your Open WebUI installation. |
| `fallback_model_id` | Open WebUI chat model ID used if no valid decision can be applied. Empty means leave the incoming model unchanged. |
| `text_decision_model` | Cloudflare model for requests without images: `typesafe/jev`, `@cf/cloudflare/clef`, or `@cf/cloudflare/clef-flash`. |
| `image_text_decision_model` | Cloudflare decision model for image requests. Prefer a Clef model so it can see image data. |
| `cloudflare_account_id` | Cloudflare account ID used in the API URL. |
| `cloudflare_api_token` | Cloudflare API token with Workers AI Read permission. It is a masked password-style valve; enter the raw token without `Bearer `. |
| `cloudflare_gateway_id` | Optional AI Gateway ID. If empty, the filter uses the `default` gateway. |
| `router_instructions` | Retained configuration note for routing guidance. Model descriptions are sent as choice-option text; this valve is not duplicated into the compact JEV/Clef request. |
| `allowed_models` | Optional Open WebUI model-ID allowlist. Only listed models can be selected. Their descriptions are used for capabilities, tools and context fit. |
| `banned_models` | Open WebUI model IDs excluded from routing. |
| `show_reasoning` | Display concise routing decision details in the chat. |
| `status` | Show status updates while routing. |
| `debug` | Enable diagnostic logging. The API token is never logged. |
| `request_timeout_seconds` | Cloudflare decision-request timeout. |

`allowed_models` takes precedence over `banned_models` in the practical sense that a model must pass both checks: if it is not allowlisted it is excluded, and a banned model is excluded even if allowlisted.

## Model Descriptions and Context Profiles

The filter does not require separate routing profiles or parse numeric context limits. Put task strengths, limitations, supported tools and an optional context label in each Open WebUI model's description. JEV/Clef uses those descriptions to select a model and score the likely context need.

Use one of these labels where appropriate:

- `S`: short context, up to 100K tokens.
- `M`: medium context, up to 250K tokens.
- `L`: long context, up to 1M tokens.

Example description:

> Fast, low-cost general assistant for short factual questions, rewriting, and simple planning. Supports native tool calling and web search. Not intended for complex coding or long multi-step reasoning. Context: S.

Models without a context label remain candidates. JEV/Clef judges them using the rest of the description and the request. These labels are qualitative guidance, not enforced token limits; retrieval content and provider-side prompt additions may change the true context size.

## Tools and Capabilities

The routing state includes tools selected for the current request (from `body` and `__metadata__` when available). Each model choice also includes that candidate's configured tool IDs, enabled built-ins/default features, and function-calling mode alongside its name and description. Open WebUI's `inlet` runs before server-side tool schemas are fully resolved, so selected tools may be represented by IDs only; when schemas are available, their names and descriptions are included. Model descriptions should explain tool purpose and limitations for better matching. The final Open WebUI request preserves the chosen preset's configured tools and knowledge.

The filter preserves the selected model's configured tools and knowledge when rebuilding the final Open WebUI request. A tool ID without a description is still provided as an ID, but adding clear tool descriptions improves routing decisions.

## Voice and Text Behavior

Open WebUI Voice Mode sets `body.features.voice` before inlet filters execute. The filter uses that flag to identify Voice Mode; it also accepts `metadata.voice`/`metadata.audio` as compatibility hints. A normal dictation recording that is transcribed into the input box is submitted as ordinary text and cannot reliably be distinguished from typed text.

The route is stored with the voice/text mode. Later messages do not call Cloudflare unless the mode changes (or a newly attached image requires a vision-capable route). On a mode change the filter evaluates the conversation and chooses again, allowing the decision to account for the conversation's context needs without a per-turn context check. Consequently, context growth alone does not trigger a route change in an unchanged text/voice mode; detecting that would require a decision request on each turn, which this filter deliberately avoids.

## Fallback and Failure Handling

Cloudflare timeouts, API errors, missing credentials, invalid responses, and choices outside the eligible candidate list use `fallback_model_id` when configured. Otherwise the incoming model is retained. A fallback is an Open WebUI chat model, never a JEV/Clef evaluator model.

The filter does not inspect generated answers for correctness and does not interrupt an in-progress response. It cannot reroute a response after generation has started.

## Troubleshooting

- **No route on a new chat:** Confirm that the selected model ID exactly matches `router_entry_model_id`, that the filter is enabled on that preset, and that at least one active model is eligible.
- **No route on Voice Mode changes:** Ensure the filter is attached to the selected response models as well as the router-entry model, and that `body.features.voice` is present in your Open WebUI version.
- **Cloudflare authentication error:** Check the account ID, token permissions, Workers AI availability, and Gateway ID. The token needs Workers AI Read permission for `/ai/run` requests.
- **Clef cannot inspect an image:** Its REST input accepts base64/data image bytes, not remote URLs. Verify that Open WebUI provides embedded image data to the filter.
- **A model is never selected:** Check its active state, allowlist/ban list, Vision capability for image requests, and its name/description in Open WebUI.
- **Target model system prompt is not applied:** The filter copies the selected model's `params.system` into the final message list. Verify the prompt is configured in that model's Open WebUI preset.

## Security and Privacy

The Cloudflare API token is stored in a secret valve and used only by the server-side filter. Never enable debug output that serializes authorization headers or request headers. Routing sends conversation text and model/tool descriptions to the configured Cloudflare decision model. Images are sent to Clef only when embedded data is available and the image decision backend is a Clef model.
